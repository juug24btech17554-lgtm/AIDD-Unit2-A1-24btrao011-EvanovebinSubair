## Reflection: Cursor compared to GitHub Copilot

Using Cursor for this project was a good way to see how a second AI coding assistant works. Compared with the GitHub Copilot demo we saw in Class 02, Cursor felt more like a partner that works on the whole project than a tool that suggests code line by line. In Agent mode, one prompt could update several functions and create a new test file, which felt faster than accepting suggestions one at a time.

Cursor also needed some correction. After my few-shot prompt, the code appeared only in the chat and was not saved into expense_splitter.py. I had to ask again in Agent mode and use the Review button before the file changed. This was my main problem, and it showed me that I must always check the file and not only the chat answer. I did not hit any free-tier limit or slowness during the work.

The prompting techniques made a clear difference. Zero-shot was enough for the simple split_equally function. Few-shot made the docstrings and error messages consistent across all functions. Chain-of-thought helped most on the rounding problem: Cursor explained why 33.33 three times gives 99.99, then fixed it using Decimal and wrote unit tests that passed.

In a real team, I would choose Cursor when a task touches several files, such as adding a feature with tests, or when the tool needs to read the whole project. I would choose Copilot for quick inline suggestions while typing inside one file, because it fits directly into the editor with little setup. Either way, a developer must review the output and run the tests before committing.
